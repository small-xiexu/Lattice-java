# Lattice 全流程真实验收手册

当前验收对象是 `/app/*` 证据型知识问答与治理工作台。旧 `/admin/*` 页面已退役，不再作为验收入口；`/api/v1/admin/*` 业务 API、CLI 和 MCP 继续保留。截至 2026-07-22，33 个首期保留能力已完成自动化覆盖，问答、五类导入、处理/审核/反馈与高风险维护已完成真实浏览器组合验收。

详细实施证据、CAP 索引和截图以 [`docs/plans/2026-07-22-前端整体重构实施计划.md`](plans/2026-07-22-%E5%89%8D%E7%AB%AF%E6%95%B4%E4%BD%93%E9%87%8D%E6%9E%84%E5%AE%9E%E6%96%BD%E8%AE%A1%E5%88%92.md) 为准。本手册只保留当前可复现的启动、验收和恢复步骤。

## 1. 验收边界

| 边界 | 当前口径 |
| --- | --- |
| 分支 | 默认直接在 `main` 验收，不自动提交 Git |
| JDK | 21 |
| 前端工具链 | Node `24.18.0`、npm `11.16.0`、`frontend/package-lock.json` |
| 后端 | Spring Boot 3.5.1，本地默认端口 `18082` |
| 数据 | PostgreSQL `ai-rag-knowledge.lattice`，Redis `127.0.0.1:6379` |
| 真实模型 | 日常回归优先 OpenAI 路由，Claude 仅用于 Anthropic 专项 |
| 权限 | 本轮不引入认证或 RBAC，高风险确认只是误操作防护 |
| 浏览器存储 | 密钥、凭据、答案、证据原文和服务端维护路径不得持久化 |
| 高风险数据 | 只使用临时 Vault/Git 与可恢复测试文章，不直接使用生产目录 |

不在首期范围：会话历史、来源范围查询、异步研究进度、SSE/WebSocket、研究任务取消与刷新后恢复。这些能力缺少对外后端契约，不得用前端假状态模拟。

## 2. 验收前准备

### 2.1 环境预检

```bash
export JAVA_HOME="$(/usr/libexec/java_home -v 21)"
```

默认复用 `vector_db` 和 `redis` 容器。不要为日常验收自动启动第二套 PostgreSQL/Redis。

```bash
./scripts/reset-lattice-schema.sh
```

该命令会删除并重建 `lattice` schema。普通前端验收禁止顺手执行。

```bash
cd frontend
nvm use
npm ci

```

开发态入口为 `http://127.0.0.1:5173/app/ask`，API 代理目标为 `18082`。

1. 打开 `/app/settings/models`。
2. 对 Provider Connection 执行连接测试。

Spring Boot 制品还必须通过：

- hash asset 返回长期 immutable 缓存。
- 缺失 asset、无扩展名 asset 和带扩展名的业务路径返回 404，不 fallback 到 HTML。
- `/admin`、`/admin/ask`、`/admin/settings`、`/admin/developer-access` 返回 404，不重定向。
- `/api/v1/admin/*`、`/actuator/*` 和 `/mcp` 不被 SPA 接管。

## 5. 真实浏览器组合任务

自动化门禁通过后，再用真实 API 和可恢复数据完成以下四组任务。每组记录请求/对象 ID、状态迁移、错误恢复、控制台结果和截图。

### 5.1 问答 -> 引用 -> 证据 -> 返回 -> 反馈

1. 在 `/app/ask` 分别核对智能、快速和深度三种模式与请求字段一致。
2. 提交一个当前知识库有证据的问题，防止重复提交。
3. 确认 `generationMode=LLM`、`modelExecutionStatus=SUCCESS`，不用 fallback 结果冒充模型成功。
4. 激活行内引用，核对证据原文、来源和支撑状态。
5. 唯一定位时展示精确片段；零匹配、多匹配、跨节点或来源歧义时降级为证据列表，不猜测位置。
6. 从证据面板返回后，焦点回到原引用。
7. 提交一次反馈，确认防重和成功回显。

2026-07-22 记录：Query `83c179eb-91a6-4d84-833f-e9d534f1b152` 为 `SUCCESS + LLM + modelExecutionStatus=SUCCESS + reviewStatus=PASSED`，2/2 引用完成校验；多匹配引用正确降级为证据列表，feedback `8` 创建成功。

### 5.2 五类导入 -> 文章搜索 -> 来源追溯

在 `/app/library/sources?action=import` 分别提交：

1. 本地多文件或拖拽目录。
2. 公开/私有 Git；私有凭据只当次提交明文，列表只显示 mask。
3. Internal Mirror。
4. 服务端目录编译。
5. 直接上传编译。

后续检查：

- source/run/job 返回真实标识与状态，异步任务不伪造同步成功。
- Git 记录可追溯到确定 commit。
- `/app/library/articles` 搜索后进入文章详情。
- 来源文件可跳转到精确 source 文件视图。
- 未收录关系对象显示未收录，不伪造可跳转链接。

2026-07-22 记录：本地多文件 source/run `7/6`，Git source/run `8/7`，Internal Mirror source/run `9/8`，服务端目录 job `732078ce-d23d-4e8b-972a-8f38bf308a8d`，直接上传 job `ea2b18ac-8abc-49d8-a51a-786aef40f9f3`。`FineController` 文章可追溯到 source `#2` 文件视图。

### 5.3 处理 -> 失败/重试/确认 -> 审核 -> 反馈治理

1. 在 `/app/activity` 核对 source run、processing task 和 compile job 的列表/详情一致。
2. 制造一个 `WAIT_CONFIRM` 的资料源匹配，查看决策摘要后只确认一次。
3. 用隔离无效文档生成真实失败 job，确认错误码与阶段可见。
4. 在重试确认框中核对影响摘要，确认一次后应复用原 job，`attemptCount` 增加而不是创建重复任务。
5. 在 `/app/reviews` 审核一条 compile review，检查乐观并发状态、审核意见和发布结果。
6. 在 `/app/feedback` 解决或忽略一条待处理反馈，检查审计时间线。

2026-07-22 记录：source run `9` 经人工确认生成 source `10` 与成功 job `cc182ad7-f1bf-4091-9b51-2357ee508f8b`；无效文档 job `3b3a5aec-b611-4b25-b8f0-3d2033bb4ce0` 在 `ingest_sources/COMPILE_EXECUTION_FAILED` 失败，重试后 `attemptCount` 从 1 变为 2 且仍如实失败。Compile review `#6` 已发布，feedback `#8` 已解决，审计 `#10/#11` 完整。

### 5.4 设置保存/测试 -> Vault 冲突 -> 差异 -> 整库回滚

普通设置：

1. 在 `/app/settings/models` 选择可用连接。
2. 不填写密钥，以原值保存，确认服务端 mask 保持且页面不回填明文。
3. 执行真实连接测试，记录可访问模型数、耗时和失败恢复。

高风险维护：

```bash
P8_VAULT_DIR="$(mktemp -d /tmp/lattice-vault-acceptance.XXXXXX)"
printf '%s\n' "$P8_VAULT_DIR"
```

1. 在 `/app/settings/maintenance` 输入上述绝对路径，建立基线 A，记录 snapshot ID 和 Git commit。
2. 选择一篇可恢复测试文章，通过文章纠错在数据库加入唯一 `DB-C` 标记。
3. 在临时 Vault 对同一文章文件加入唯一 `VAULT-D` 标记。
4. 执行安全同步，必须返回冲突且不覆盖数据库。
5. 先输入错误强制同步目标，确认前端阻止 mutation；再输入精确 Vault 路径并显式确认一次。
6. 确认只有目标文章被同步，数据库包含 `VAULT-D` 且不再包含 `DB-C`。
7. 建立修改态基线 B，然后选回基线 A 预览差异。
8. 只在预览返回目标/当前 commit 和变更文件后，才准备整库回滚。
9. 先输入错误 snapshot ID，确认 HEAD 和数据库不变；再输入基线 A 的精确 ID 并确认一次。
10. 最终确认数据库文章和审核状态恢复，`DB-C/VAULT-D` 均消失，临时 Git HEAD 回到基线 A 且工作区干净。

2026-07-22 记录：`local_openai` 同值保存后连接测试成功，可访问 20 个模型，耗时 38 ms。临时 Vault 基线 A 为 `#8/d325e1dd9896`，安全同步返回 1 冲突、0 同步/50 跳过；强制同步只写入 1 篇。修改态基线 B 为 `#10/bc6c2153610d`，差异为 2 个文件。回滚到快照 8 后生成记录 `#11`，数据库文章恢复 `passed`，Git HEAD 回到 `d325e1dd9896` 且干净。

- `localStorage`、`sessionStorage`、IndexedDB 不包含密钥、答案、证据或 Vault 绝对路径。
