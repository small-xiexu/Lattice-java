# Lattice 前端整体重构实施计划

> 唯一进度台账。后续前端设计、实现、验证与直接替换均以本文件为准。

## 1. 目标与边界

### 1.1 目标

- 把当前多页静态管理后台重构为“证据型知识问答与治理工作台”；“AI 知识研究工作台”作为后续愿景，不用首期无法支撑的能力抬高定位。
- 将普通用户工作区、知识治理流程、系统配置与开发接入明确分层。
- 保留现有 Spring Boot API、单服务部署和本地开发入口。
- 首期界面只承诺现有 API 可真实支撑的能力，不用前端状态模拟后端尚未提供的会话、流式进度或任务控制。
- 建立可维护、可测试的前端工程与设计系统，完成后直接替换旧后台。

### 1.2 本轮确认范围

- 页面地图与路由层级。
- 核心页面低保真布局。
- 全局设计 Token 与交互原则。
- 现有 API 能力矩阵、首期产品边界与后置能力。
- 后续分阶段实施、验证和直接替换清单。

### 1.3 阶段边界

- P0 只冻结契约、能力、工程和直接替换规则，不修改 `src/main/java/**`、`src/test/java/**` 或现有 `src/main/resources/static/admin/**`。
- P0 不新增、删除或调整后端 API，不执行数据库重建、真实模型调用或浏览器验收。
- P0 退出门禁通过后，P1 开始创建前端工程、集成 Spring Boot，并同步删除旧页面映射与静态资源。
- 异步 Deep Research、SSE / WebSocket、会话历史、限定来源和研究任务控制不纳入首期前端实现；如需支持，必须另立后端契约与实施项。

### 3.1 台账回写规则

- 本文件是状态唯一真源；测试报告、截图和构建日志可作为外部证据，但必须由本文件链接并给出结论。
- 子任务状态只能为 `待实施`、`进行中`、`阻塞`、`待验证`、`已完成`；任何未经验证的交付物不得标记已完成。
- 每个子任务必须记录：输入/契约、交付物、验证方式、验收证据和下一步。状态变化时当即回写，不在阶段结束时集中补写。
- P0-P8 默认直接在 `main` 分支执行；每个阶段开始或恢复前先核对当前分支与工作区，保留用户已有变更。切换分支本身不作为任务完成证据。
- 执行顺序固定为 `P0 -> P1 -> P2a -> P2b -> P3 -> P4 -> P5 -> P6 -> P7 -> P8`；前一阶段退出门禁未通过，不得将后一阶段标记为进行中。
- 能力覆盖率分母只包含“当前 Web 可操作能力 + 已明确要求由前端承接的系统能力”中决策为“保留”的原子项；后端、CLI 或 MCP 专属能力不自动进入分母。
- “后置”和“退场”项必须记录决策理由并经人工确认；“待确认”项存在时，P7 不得开始全量覆盖收口。

## 4. 任务视角与安全边界

| 任务视角 | 首要任务 | 默认交互中不主动呈现的内容 |
| --- | --- | --- |
| 知识使用者 | 选择查询模式、提交单次问题、阅读答案、核对引用、提交反馈 | 模型连接、向量维度、解析策略、底层检索权重 |
| 知识运营者 | 导入资料、查看处理进度、浏览知识文章、处理人工审核与反馈 | API Key、底层模型参数、开发接入模板 |
| 系统管理员 | 配置模型绑定、向量、文档解析与检索参数，执行高风险维护 | 普通问答引导、重复的业务入口说明 |
| 开发者 | 获取 HTTP API、MCP、CLI 的地址、模板和验证方式 | 业务运营统计和知识治理表单 |

当前项目没有认证与 RBAC，本次重构不引入认证、授权或角色隐藏，也不将其作为实施门禁。上表只表示任务分层，不是安全边界；首期所有功能均可见，不设置无真实身份信息支撑的用户菜单。高风险操作的影响摘要、预览和确认只用于减少误操作，不宣称为权限控制。

### 4.1 P0.4 冻结结论

| 边界 | 首期约束 | 验收方式 |
| --- | --- | --- |
| 功能可见性 | 33 个保留能力全部可见；不显示用户头像、角色、租户或权限菜单 | 路由表和导航测试不以任何虚构身份为前提 |
| 部署前提 | 默认为可信网络中的管理工具；认证/RBAC 不属本次范围，也不阻断 P0-P8 | README/启动清单必须与实际暴露边界一致，不出现“已有权限保护”类描述 |
| 模型/解析凭据 | `apiKey`、`credentialJson`、资料源 `secret` 仅在当次表单内存中存在，用密码型控件；列表/详情只消费 mask/configured 标记，编辑时不回填明文 | 搜索 Web Storage/日志/错误展示，组件测试验证 DOM 和客户端缓存不含明文 |
| 浏览器存储 | 密钥、凭据、答案、证据原文、`evidenceJson`、原始错误栈和服务端维护路径禁止写入 `localStorage/sessionStorage/IndexedDB`；查询结果和维护输入只放应用内存 | 存储边界单测 + Playwright 检查 Web Storage/IndexedDB |
| 草稿与偏好 | 只有无敏感字段的问答/表单草稿可写 `sessionStorage`，必须带 schema 版本、TTL 和容量上限；仅主题等无敏感偏好可写 `localStorage` | 白名单序列化测试，过期/版本变化时清除 |
| 客户端日志 | 不记录密钥、multipart 内容、答案、证据、`errorMessage/evidenceJson`原文或服务端路径；只记录请求类型、状态码、可公开错误码和随机关联标识 | 对错误、上传和密钥提交场景做 console/测试捕获 |
| 高风险写操作 | 弹窗显示动作、对象、范围和不可自动恢复的后果；链接增强必须先预览，Vault 强制同步和整库回滚必须输入目标标识 | 组件/Playwright 验证未确认时无 mutation，目标不匹配时按钮不可用 |

当前代码核对证据：未发现 `SecurityFilterChain`、Sa-Token 调用、权限注解或 RBAC 实现；旧静态前端未使用 `localStorage`、`sessionStorage` 或 IndexedDB；LLM 和文档解析配置响应使用掩码/已配置标记，请求密钥字段已排除 `toString`。

## 5. 产品结构与页面地图

### 5.1 全局导航

```text
Lattice
├── 问答与研究                         普通用户主入口
├── 知识库
│   ├── 资料源
│   ├── 知识文章
│   └── 知识质量
├── 处理中心
│   ├── 运行任务
│   ├── 人工审核
│   └── 结果反馈
├── --------------------------------
├── 系统设置                           侧栏底部
│   └── 高级维护
├── 开发者接入                         侧栏底部
└── 服务状态                           侧栏底部固定状态
```

导航规则：

- 一级导航只使用图标、短标签和必要的未处理数量，不放功能说明文案。
- “知识库”与“处理中心”允许展开二级导航，其余入口直接进入页面。
- 当前页面必须有稳定 URL；列表筛选、选中对象和详情抽屉状态可回写 URL。
- 服务状态只展示 `正常 / 降级 / 不可用`，详细诊断进入独立状态面板。
- 移动端使用顶部栏加抽屉导航，不在同一级同时使用侧栏和底部导航。

### 5.2 Query 与关键交互契约

本表只固定影响产品形态的关键契约与明确边界；所有“保留”原子能力的完整请求、响应、错误与状态迁移矩阵由 P0.2 冻结。

| 能力 | 当前契约 | 首期决策 |
| --- | --- | --- |
| 查询提交 | `POST /api/v1/query`，同步返回 JSON | 支持；统一展示等待、成功、部分回答、证据不足和失败状态 |
| 查询模式 | 默认自动路由；`forceSimple` / `forceDeep` 可强制路径 | 使用“智能 / 快速 / 深度”三段模式，不使用含义不实的两段开关 |
| 回答与引用 | 返回 answer、sources、articles、citationMarkers 等结果 | 支持正文、结果语义、反馈和引用核验 |
| 引用位置 | `citationMarkers` 含 markerId、引用字面量和顺序，但不含正文 offset 或结构化块位置 | P0 先做 Markdown AST 定位原型；无法唯一匹配时禁止错绑，降级为证据列表 |
| Deep Research | 同一请求内同步执行，最终返回聚合摘要 | 支持等待状态、最终报告和聚合指标；不展示虚构的实时阶段 |
| 查询历史与多轮会话 | 无会话或历史查询接口 | 首期不展示最近会话，不承诺继续追问上下文 |
| 限定来源查询 | `QueryRequest` 无 source scope 字段 | 首期不展示来源范围选择器 |
| 研究进度、中间发现和活动流 | 无对外状态或事件接口 | 首期不做轮询、SSE、WebSocket、活动时间线和中间发现 |
| 研究计划编辑、取消、恢复 | 无对外编辑、取消、恢复或按 queryId 重载接口 | 首期不提供“调整研究范围”“停止研究”和独立可恢复研究页 |
| 查询结果恢复 | 无查询历史和按 queryId 重载完整答案接口 | 同一 SPA 会话内使用应用内存保留当前结果；刷新/重开不恢复答案，仅恢复输入草稿并明确提示 |
| 知识搜索 | `GET /api/v1/search` | 顶栏只搜索知识内容；命令面板同时支持页面跳转 |
| 文章来源与关系 | 文章详情返回 sourceId、sourcePaths、dependsOn、related | 支持来源跳转和关系列表；无法确认的具体同步批次不做推断 |

以下能力只有在后端提供明确契约后才能进入前端计划：创建异步研究任务、查询任务快照、订阅事件、取消任务、按 queryId 重载报告、保存会话上下文、限定检索来源。

### 5.7 前端 API 契约矩阵

`Q` 表示 `/api/v1`，`A` 表示 `/api/v1/admin`。本矩阵不改动后端契约，不把前端约束宣称为后端保证。

全局契约：

- Query/Search 子域业务错误为 `QueryErrorResponse {code,message}`，已明确状态包括 `400/409/422/503/504`；其他 Admin/Compile 异常主要为 `CompileErrorResponse {code,message}`，已明确状态包括 `400/409/413/500/503`。参数绑定、代理和非预期错误可能不是该包装，API Client 必须兼容 Spring Problem Detail、JSON 非标准体和无响应体，统一归一为 `status/code/message/fieldErrors/retryable`。
- 只有资料源列表提供 `page/size/total/items` 真分页。其余列表为有界 `limit + count/items`、无界 `count/items` 或数组；前端不伪造服务端翻页，数量过大时通过本地虚拟化或单列后端分页需求处理。
- 只轮询有真实可变状态且有详情/列表查询契约的 source run、compile job 和 processing task。初始间隔 `2s`，连续无变化逐步退避至 `5s`；页面隐藏时降频，终态、离开路由或请求失效时停止。
- 当前所有写接口均无通用 idempotency key。默认不自动重试 mutation，同一资源同一动作只允许一个在途请求；成功后使用返回标识/状态失效精确缓存。`PUT` 配置是最后写入覆盖，不等于有版本并发保护。
- 只有文章审核和编译审核动作提供 `expectedReviewStatus` 乐观并发校验；资料源同步可返回 `409 SOURCE_SYNC_CONFLICT`。其余写操作没有版本号，操作前必须重取目标摘要，但仍不能消除最后写入竞争。
- 当前无任务取消 API。`AbortSignal` 只终止浏览器等待和后续状态写入，不声称取消后端 Query、编译、同步、重建或维护任务。

P0.2 结论：33 个保留项均有可用现有契约，未发现必须先修改后端才能进入实施的阻塞项。无通用幂等键、无通用取消、多数列表无真分页和多数 mutation 无版本号已作为前端约束显式接受；若后续实现发现上述约束导致目标用例无法完成，必须将对应 CAP 改为 `阻塞`并单列后端变更，不在前端静默补齐。

### 5.8 引用定位原型与冻结规则

`QueryCitationMarkerResponse` 实际只提供 `markerOrdinal`、`markerId`、`citationLiteral(s)`、`claimText`、`sourceCount`和 `sources`，没有正文 offset 或结构化块位置。首期因此冻结为两级承诺：

1. 使用 `unified + remark-parse + remark-gfm` 生成 GFM AST，只在可展示正文的 `text` 节点中匹配 `citationLiteral`，代码块、行内代码和 HTML 不参与精确绑定。
2. 仅当字面量在全部合格正文节点中恰好出现一次，且 marker 恰好对应一个无歧义来源时，使用 AST `position.start.offset` 加节点内局部偏移生成精确区间。
3. 零匹配、同节点或跨节点多匹配、字面量跨节点、仅出现在代码/HTML 中、或来源数不为 1，均降级为该 marker 的证据列表；不根据 `claimText`、顺序或最近距离猜测位置。
4. 渲染后的 marker 必须保留 `markerId`、可访问名称和双向焦点返回；Markdown 净化在定位与渲染的同一 AST 管线中完成，避免净化前后位置漂移。

原型在仓库外的系统临时目录运行，使用 `unified@11.0.5`、`remark-parse@11.0.0`、`remark-gfm@4.0.1`和 `unist-util-visit@5.1.0`。实测结果：

| 样例 | AST 结果 | 冻结行为 |
| --- | --- | --- |
| 单一段落中唯一 `[1]` | `paragraph`，offset `6..9` | 精确绑定 |
| 同一段落中两个 `[1]` | 同节点命中 2 次 | 降级为证据列表 |
| 两个段落分别出现 `[1]` | 两个 `paragraph` 节点各命中 1 次 | 降级为证据列表 |
| GFM 表格单元格中唯一 `[2]` | `tableCell`，offset `21..24` | 精确绑定 |
| 代码块中 `[3]` | 合格正文节点命中 0 次 | 降级为证据列表 |
| `[**4**]` 将 `[4]` 拆到多节点 | 单节点精确命中 0 次 | 降级为证据列表 |
| 唯一 `[5]` 但 `sourceCount=2` | 文本唯一、来源有歧义 | 降级为证据列表 |

P0.3 结论：当前后端契约可支撑“唯一正文节点精确绑定 + 其余全部安全降级”，不承诺所有引用均能行内定位。若未来要求无降级精确定位，后端必须增加稳定的结构块标识和 offset 契约。

## 6. 页面设计原则

1. 研究内容优先：回答、报告和原始证据占据主要视口，状态与配置退到上下文面板。
2. 搜索与对话分工：查找文档时展示结果列表和过滤器，需要综合答案时进入问答或研究模式。
3. 引用可验证：唯一匹配时，行内引用直接打开对应证据片段；匹配有歧义时打开已绑定证据列表，不错绑也不将引用只放在页底。
4. 运行状态真实：只展示 API 可获得的阶段、进度和恢复动作；同步 Query 只展示等待与最终状态，不模拟中间过程。
5. 渐进披露：默认展示用户当前需要的信息，检索审计、原始 JSON 和高级参数按需展开。
6. 页面不是卡片集合：页面区段使用布局和分隔线，卡片只用于可重复对象、状态摘要和浮层。
7. 一个页面一个主操作：导入、提问、保存配置等主操作保持唯一，危险操作独立放置。

## 8. 设计系统基线

### 8.1 视觉原则

- 风格：安静、精确、内容优先的桌面生产力工具，不做营销页构图。

### 8.8 交互与可访问性门禁

- 每页提供可见于焦点时的“跳到主内容”链接，使用 `header` / `nav` / `main` / `aside` 等 landmark，页面标题层级连续且每页只有一个 `h1`。
- 所有核心功能可通过键盘完成，Tab 顺序与视觉顺序一致。
- 图标按钮必须有可访问名称；Tooltip 不能成为唯一说明来源。
- 正常文本对比度至少 `4.5:1`，大文本与非文本控件至少 `3:1`。
- 表单保留可见 Label，错误显示在对应字段附近，并聚焦第一个错误字段。
- 异步操作需要 Loading、成功和失败状态；按钮提交期间防止重复操作，状态更新通过适当的 `aria-live` 区域播报且不抢夺焦点。
- 可排序表格必须使用语义化表头并维护 `aria-sort`；数据表内部可有受控横向滚动，但不得造成页面级横向滚动。
- 空列表、加载失败、无搜索结果、权限不足和服务降级均有独立状态。
- 浏览器返回必须恢复列表筛选、滚动位置和问答输入草稿。
- 在 `200%` 浏览器缩放下不遮挡核心操作、不丢失内容；系统 `forced-colors` 模式下焦点、边界和状态仍可识别。
- 移动端输入字号不小于 `16px`，Sheet、底部操作栏和 Toast 不遮挡安全区或键盘。
- 长列表超过 50 项评估虚拟化；路由级功能按需加载。

### 8.9 客户端状态归属

| 状态 | 归属 | 约束 |
| --- | --- | --- |
| 当前路由、筛选、排序、分页、可重载的选中对象 | URL | 可复制、刷新和前进/后退恢复 |
| 服务端数据、请求状态、缓存和 mutation | TanStack Query | query key 必须稳定，mutation 后精确失效 |
| 当前查询结果与引用选中状态 | 应用内存 | 同一 SPA 会话及浏览器后退可恢复；不写入 `sessionStorage` / `localStorage`，刷新后明确提示不可恢复 |
| 面板展开、临时高亮、表单/问答输入草稿和滚动锚点 | 组件状态或 `sessionStorage` | 只保存当前标签页中有意义的短期状态，草稿需定义 schema 版本、TTL 和容量上限 |
| 身份、主题等跨会话偏好 | 服务端或 `localStorage` | 只在存在明确产品需求时引入 |

- P2a 不引入 Zustand、Jotai 等全局状态库；只有 P2b 原型证明路由、服务端缓存和局部状态无法合理承载共享状态时，才单独评审。
- 在未完成敏感数据分级、存储威胁分析和清理策略前，不得把答案、证据原文和 API 密钥写入任何浏览器持久存储。
- 浏览器后退恢复筛选、选中项和滚动锚点；虚拟列表优先按稳定 item key 恢复，不仅记录像素位置。
- 路由切换后将焦点移到主内容标题；关闭 Drawer、Sheet 或 Dialog 后恢复触发元素焦点。
- 首期界面文案使用简体中文，按 feature 集中管理，不在组件中散落重复字符串；未有多语言需求前不引入完整 i18n 框架。

## 9. 前端工程边界

### 9.1 推荐技术栈

- React + TypeScript + Vite。
- React Router 管理可分享、可恢复的页面状态。
- TanStack Query 管理 API 缓存、轮询、刷新、mutation 和失败恢复。
- Radix Primitives / shadcn/ui 提供无障碍交互基础，组件视觉完全服从本计划 Token。
- Tailwind CSS 使用语义 Token，不在业务组件散落任意色值。
- Lucide React 作为唯一通用图标库。
- `react-markdown + remark-gfm + rehype-sanitize` 渲染回答、文章和研究报告。
- MSW 提供可重复的成功、空数据、部分回答、失败和超时模拟。
- Vitest + Testing Library 覆盖组件和交互；Playwright 覆盖关键页面链路。
- React Hook Form + Zod 在 P6 出现多字段、跨字段校验的设置表单时再引入，不作为 P1 强制依赖。
- 首期不引入 SSE、EventSource 或 WebSocket 客户端；JSON 请求支持 `AbortSignal` 仅用于终止浏览器等待，不宣称后端任务已取消。

### 9.2 工程结构建议

```text
frontend/
├── src/
│   ├── app/                 路由、Provider、App Shell
│   ├── features/            ask、library、activity、reviews、feedback、settings、developer
│   ├── components/          通用业务无关组件
│   ├── api/                 API Client、类型、query keys
│   ├── styles/              Token、全局样式、主题
│   └── test/                测试工具与 mock
├── package.json
├── tsconfig.json
└── vite.config.ts
```

- 开发态由 Vite 提供 HMR，并代理 `/api`、`/actuator` 和 `/mcp` 到 Spring Boot `18082`。
- 生产构建输出带 hash 的静态资源，由 Spring Boot 同一制品提供，不引入 Next.js 或第二个运行时服务。
- 构建产物不手工编辑；源码与构建产物边界在 P1 中明确并纳入 Maven 构建。
- 禁止继续使用字符串分片加 `new Function` 组装运行时代码。
- API 类型先按现有响应契约定义；只有确认接口无法支撑目标交互时，才单独提出后端变更。
- 路由级页面默认分包，Markdown、代码高亮和复杂设置表单按需加载；P1 记录初始构建的 gzip 体积作为后续基线。
- 列表优先使用服务端分页；确需在客户端展示 50 项以上数据时，使用 `@tanstack/react-virtual` 并按稳定 item key 恢复位置。
- Storybook / Ladle 不作为首期门禁；当共享组件在三个以上 feature 复用后，再评估是否引入独立组件工作台。

#### P8.1 首轮失败归因

- 失败类型：真实模型调用失败；检索、fallback、citation binding、证据查看和反馈写入均成功，不修改这些主链环节。
- 复现证据：连接探测可访问 `/v1/models` 并返回 20 个模型，`gpt-5.5` 在模型列表中；当前模型探测返回 `400 Bad Request, Upstream request failed`。同一连接和模型直接调用 `/v1/chat/completions`，省略 `max_tokens` 时返回 200；当前已保存档案配置 `maxTokens=4096`，模型探测即使不传档案也会强制补 `max_tokens=64`。
- 根因：可空的输出 token 上限在 OpenAI-compatible 调用中被强制转换为旧 `max_tokens` 字段，当前上游不接受该字段；不是密钥、连接、模型名称、检索证据或前端解析问题。
- 通用修复点：模型档案未配置输出上限时不发送 `max_tokens`，探测端保持该可空语义；不依据 `gpt-5.5`、业务问题、资料名称或答案内容写特判。
- 影响与验证：只调整当前模型档案和模型探测参数组装，定向覆盖“空上限不发送、显式上限仍受探测上限保护”，再以真实浏览器要求 `modelExecutionStatus=SUCCESS`、非 fallback、引用与反馈闭环全部通过；不得用 fallback outcome 冒充真实模型成功。
- 复验结论：OpenAI-compatible 探针在空上限时不再发送 `max_tokens`，模型 1 探针和 Query 实际执行均成功；P8.1 第二轮满足真实模型、引用降级、证据、焦点返回和反馈闭环门禁，本根因已关闭。

P8 退出门禁：已通过。问答与引用、全部导入方式、处理/重试/确认、文章与质量治理、设置维护的真实浏览器验收通过，可访问性、响应式和文档同步完成，无稳定观察窗口或旧资源退场后置阶段。
