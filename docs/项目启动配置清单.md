# Lattice Java 项目启动配置清单

当前开发基线为 JDK 21 + Spring Boot 3.5.1 + React/Vite。后端默认复用本机 `vector_db` 和 `redis` 容器，业务 schema 固定为 `lattice`。本地联调使用 `18082`，前端 HMR 使用 `5173`；生产构建只产出一个包含 `/app/*` 的 Spring Boot JAR。

## 1. 环境基线

| 项 | 版本/默认值 | 是否阻断启动 |
| --- | --- | --- |
| JDK | 21 | 是 |
| Maven | 使用用户全局本地仓库 `/Users/sxie/maven/repository` | 是 |
| PostgreSQL | `127.0.0.1:5432/ai-rag-knowledge`，容器 `vector_db` | 是 |
| Redis | `127.0.0.1:6379`，容器 `redis` | 是 |
| 业务 schema | `lattice` | 是 |
| Node | `24.18.0` | 仅本地前端 HMR/独立前端门禁需要 |
| npm | `11.16.0` | 仅本地前端 HMR/独立前端门禁需要 |

Maven 生产构建使用 `frontend-maven-plugin 1.15.4` 将 Node/npm 下载到 `target/frontend-toolchain`，不依赖本机 Node 版本。前端唯一 lockfile 是 `frontend/package-lock.json`，不使用 pnpm 或 yarn。

环境预检：

```bash
export JAVA_HOME="$(/usr/libexec/java_home -v 21)"
java -version
mvn -version
docker ps --format '{{.Names}}'
```

需要运行前端 HMR 时再检查：

```bash
cd frontend
npm --version
node --version
```

`node --version` 应为 `v24.18.0`，`npm --version` 应为 `11.16.0`。`.nvmrc` 已固定 Node 版本，可使用 `nvm use`。

## 2. 依赖服务与 schema

默认直接复用现有容器：

```bash
docker ps --format '{{.Names}}'
```

应至少看到：

- `vector_db`
- `redis`

只有这两个容器不存在时，才使用仓库 `docker-compose.yml`：

```bash
docker compose up -d postgres redis
docker compose ps
```

项目不使用 Flyway。首次启动、DDL 变更或需要清空开发数据时，显式执行：

```bash
./scripts/reset-lattice-schema.sh
```

该脚本会删除并重建 `ai-rag-knowledge.lattice`，然后执行 `src/main/resources/db/schema.sql`。这是破坏性操作，不要对需保留数据的环境执行。

## 3. 运行配置

### 3.1 数据库与 Redis

`scripts/run-local-dev.sh` 已固定 `local-dev` profile、`lattice` schema 和默认端口 `18082`。非默认环境可覆盖：

| 变量 | 默认值 |
| --- | --- |
| `LATTICE_DEV_DB_NAME` | `ai-rag-knowledge` |
| `LATTICE_DEV_DB_HOST` | `127.0.0.1` |
| `LATTICE_DEV_DB_PORT` | `5432` |
| `SPRING_DATASOURCE_USERNAME` | `postgres` |
| `SPRING_DATASOURCE_PASSWORD` | `postgres` |
| `LATTICE_REDIS_HOST` | `127.0.0.1` |
| `LATTICE_REDIS_PORT` | `6379` |
| `SERVER_PORT` | `18082` |

必须手动启动时，使用同一口径：

```bash
export SPRING_PROFILES_ACTIVE=local-dev
export SERVER_PORT=18082
export SPRING_DATASOURCE_URL='jdbc:postgresql://127.0.0.1:5432/ai-rag-knowledge?currentSchema=lattice'
export SPRING_DATASOURCE_USERNAME=postgres
export SPRING_DATASOURCE_PASSWORD=postgres
export LATTICE_REDIS_HOST=127.0.0.1
export LATTICE_REDIS_PORT=6379
```

### 3.2 真实模型

只做启动和页面骨架检查时，占位 Key 不会阻止服务启动。要验收编译、问答、审查或纠错，必须在 `/app/settings/models` 配置真实 Provider Connection、Model Profile 和 Agent Binding。

也可以通过私有环境变量注入默认 Provider：

```bash
export SPRING_AI_OPENAI_API_KEY='<real-key>'
export SPRING_AI_OPENAI_BASE_URL='<openai-compatible-base-url>'
export SPRING_AI_ANTHROPIC_API_KEY='<real-key>'
export SPRING_AI_ANTHROPIC_BASE_URL='<anthropic-base-url>'
export LATTICE_LLM_SECRET_ENCRYPTION_KEY='<32-or-more-byte-secret>'
```

明文密钥不得写入仓库、命令输出或浏览器存储。日常回归默认使用 OpenAI 路由；只有专项验证 Anthropic 兼容性时才切到 Claude。

Deep Research 启动期缺少绑定只告警，运行期仍 fail-closed。不验收 Deep Research 时可临时关闭启动校验：

```bash
export LATTICE_LLM_DEEP_RESEARCH_STARTUP_VALIDATION_ENABLED=false
```

## 4. 启动方式

### 4.1 后端与已构建前端

日常本地联调：

```bash
./scripts/run-local-dev.sh
```

需要先重建 schema 时：

```bash
./scripts/run-local-dev.sh --reset-schema
```

脚本会启动 Spring Boot `18082`。如果 `target/generated-resources/frontend/static/app` 已由前端或 Maven 构建生成，可直接打开 `http://127.0.0.1:18082/app/ask`。

### 4.2 前端 HMR

先保持后端 `18082` 运行，再在第二个终端执行：

```bash
cd frontend
nvm use
npm ci
npm run dev
```

打开 `http://127.0.0.1:5173/app/ask`。Vite 会将 `/api`、`/actuator` 和 `/mcp` 代理到 `http://127.0.0.1:18082`。

`npm ci` 用于首次安装或 lockfile 变更；不提交 `node_modules`、`frontend/dist` 或 `target/`。

### 4.3 Maven 单制品

```bash
export JAVA_HOME="$(/usr/libexec/java_home -v 21)"
mvn -s .codex/maven-settings.xml clean package
java -jar target/lattice-java-1.0-SNAPSHOT.jar
```

Maven 会顺序执行：

1. 隔离安装 Node `24.18.0` 和 npm `11.16.0`。
2. `npm ci --no-audit --no-fund`。
3. lint、typecheck、Vitest、Vite build。
4. Java 测试与 Spring Boot 打包。

前端产物只写入 `target/generated-resources/frontend/static/app`，再被纳入 JAR。不回写 `src/main/resources/static`，生产 source map 关闭。

## 5. 启动验证

最少检查：

```bash
curl -fsS http://127.0.0.1:18082/actuator/health
docker exec vector_db psql -U postgres -d ai-rag-knowledge -c '\dt lattice.*'
curl -I http://127.0.0.1:18082/app/ask
```

预期：

- 日志出现 `Started LatticeApplication`。
- 健康检查返回 `UP`。
- `lattice` 业务表存在。
- `/app/ask` 返回 SPA HTML，无扩展名的 `/app/*` 深链接可刷新恢复。
- `/admin`、`/admin/ask`、`/admin/settings` 均返回 404，不重定向。
- `/api/v1/admin/*`、`/actuator/*` 和 `/mcp` 仍按各自协议响应，不返回 SPA HTML。

## 6. 当前 Web 入口

| 路由 | 主要用途 |
| --- | --- |
| `/app/ask` | 智能/快速/深度问答、引用与反馈 |
| `/app/library/sources` | 资料源、五类导入与凭据 |
| `/app/library/sources/:sourceId` | 资料源文件、校验与处理历史 |
| `/app/library/articles` | 文章搜索、筛选与热点刷新 |
| `/app/library/articles/:articleKey` | 文章详情、来源追溯、快照和治理 |
| `/app/library/quality` | 质量、覆盖、Lint、知识检查、链接增强和 Fact Card |
| `/app/activity` | processing task、source run 和 compile job |
| `/app/reviews` | 编译审核、Query Pending 和审核策略 |
| `/app/feedback` | Query 结果反馈治理 |
| `/app/settings/models` | Provider、模型档案、Agent 绑定与连接测试 |
| `/app/settings/vector` | 向量配置、状态和索引重建 |
| `/app/settings/parsing` | 文档解析 Provider、连接和默认策略 |
| `/app/settings/retrieval` | 检索参数、审计和切片重建 |
| `/app/settings/maintenance` | Vault 导出/同步、仓库基线、差异和整库回滚 |
| `/app/developer` | HTTP API、CLI、MCP 模板和健康检查 |

首次真实联调顺序：

1. 在 `/app/settings/models` 配置并测试连接、模型与绑定。
2. 在 `/app/settings/vector` 和 `/app/settings/parsing` 核对向量与解析策略。
3. 在 `/app/library/sources?action=import` 导入资料。
4. 在 `/app/activity` 跟踪 source run、processing task 和 compile job，处理失败、重试或人工确认。
5. 在 `/app/library/articles` 搜索文章并核对来源。
6. 在 `/app/ask` 完成问答、引用核验和反馈。

## 8. 常见问题

### 前端页面 404

- 本地 HMR 应访问 `http://127.0.0.1:5173/app/ask`。
- Spring Boot 托管页面需先生成 `target/generated-resources/frontend/static/app/index.html`，可执行 `npm run build` 或 Maven `package`。
- `/admin/*` 404 是预期行为，不提供兼容重定向。

### 数据库可连接但没有业务表

检查 `currentSchema=lattice` 且已执行 `./scripts/reset-lattice-schema.sh`。不要恢复 Flyway 或沿用旧 `flyway_schema_history`。

### Redis 连接失败

检查 `redis` 容器、`LATTICE_REDIS_HOST` 和 `LATTICE_REDIS_PORT`。

### 真实模型调用失败

在 `/app/settings/models` 分别执行连接测试和模型测试，再核对 Agent Binding。连接可用不代表模型可用，模型可用也不代表 Deep Research 四个角色已完整绑定。

### 高风险维护

Vault 强制同步与整库回滚只能在 `/app/settings/maintenance` 中先预览影响，再输入精确目标标识确认。验收必须使用 `mktemp -d` 创建的临时 Vault 和可恢复测试数据，不直接使用生产目录。
